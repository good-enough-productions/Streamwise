How-to Guide

  1. Add Media: Tap the Floating Action Button (+) to manually add a show or movie to your watchlist, or share a link from IMDb, Letterboxd, or any other source directly to the app using the Android Share sheet.
  2. Sync Streaming Availability: Tap the refresh icon (↺) at the top of the Watchlist tab to immediately trigger a TMDB API lookup for every item in your queue. Real provider data (Netflix, Hulu, Max, etc.) will appear on each card once your TMDB API key is configured.
  3. Configure Your TMDB API Key: Navigate to the Settings tab and paste your key into the "TMDB API Key" field. This key is saved locally in SharedPreferences and used by the background worker.
  4. Manage Subscriptions: Navigate to the My Services tab to toggle your active subscriptions and set their monthly costs for ROI calculations.
  5. Start Watching: On the Watchlist tab, optionally filter titles by "Available on My Services". Tap Watch on any item to flag it as your active viewing intent.
  6. Log Sessions: Next time you open the app after marking an intent, it automatically prompts a check-in sheet. Log the session as Finished, Partial, or Something Else, along with duration.
  7. Analyze Budget ROI: Check the Budget ROI tab to see cost-per-hour for each subscription, with flagging for services under 3 hours/month of tracked use.

Session Changelog — AI Studio Export Fix (2026-05-31)

The app was exported from Google AI Studio with several issues that prevented it from building, running, or displaying correct data locally. Below is the full chronological log of everything diagnosed and fixed.

b28c28d   CI: Fix ADB Deploy to use mDNS Wireless Debugging Auto-Discovery

Problem: The GitHub Actions workflow referenced a hard-coded IP:port for ADB which becomes stale every time the phone reconnects to Wi-Fi.
Fix: Rewrote the deploy step to auto-detect the active wireless device serial from adb devices output, matching the mDNS TLS service name (_adb-tls-connect._tcp). Device is now discovered dynamically.

6e4394e   Build: Bump Gradle Wrapper to 9.3.1; Add deploy.ps1

Problem: The project shipped with a Gradle wrapper pinned to 8.11.1, which is incompatible with Android Gradle Plugin 9.1.1. Attempting any local build failed immediately with a version mismatch error.
Fix: Updated gradle/wrapper/gradle-wrapper.properties to use gradle-9.3.1-bin.zip (the minimum version supported by AGP 9.1.1). Also added deploy.ps1 to the project root — a one-command PowerShell script that builds, installs, and launches the app on a wirelessly connected phone.

2c6a8e1 / 957cedd   Feat: Real TMDB Integration; Remove Fake Provider Data

Problem: The AI Studio export contained a function (simulateTmdbWatchProviderLookUp) that randomly assigned fake streaming providers like "netflix,hulu,max" to every item, regardless of actual availability. The Settings tab and TMDB API key input were not wired to any real network calls.
Fix: Replaced the mock function entirely with a full Retrofit implementation in TmdbApiService.kt and TmdbClient.kt. The AvailabilitySyncWorker now calls TMDB's search/movie endpoint by title, then fetches movie/{id}/watch/providers for US flatrate availability. Provider names are mapped to local IDs (netflix, hulu, max, disney, prime, apple). Results are persisted to Room and shown as colored chips on each card. The worker respects a 1-second rate-limit delay between items.

1e56933   Feat: Add "Sync Now" Button (↺) to Watchlist Tab

Problem: After wiring up real TMDB calls, there was no way to trigger an immediate sync from inside the app — users had to wait for the 4-hour periodic WorkManager schedule.
Fix: Added a small IconButton using Icons.Default.Refresh to the right side of the filter chip row in WatchlistTabContent. Tapping it calls viewModel.triggerImmediateSync(), which enqueues a one-shot AvailabilitySyncWorker request with a CONNECTED network constraint and immediately shows a status message.

7d3b680   Fix: Add INTERNET Permission; Bump Room DB to v2 to Clear Fake Seed Data

Problem 1 — SecurityException: Despite adding real Retrofit calls, the background worker was silently failing. Inspecting logs revealed a java.lang.SecurityException: Permission denied (missing INTERNET permission?) thrown inside OkHttp. The AI Studio export never declared INTERNET in the manifest.
Fix: Added <uses-permission android:name="android.permission.INTERNET" /> to AndroidManifest.xml.

Problem 2 — Stale Mock Data in Database: Even after adding the permission, existing watchlist items still displayed fake provider badges because the mock values ("netflix,hulu,max") were already written to the Room SQLite database on the phone's local storage. The new worker code that sets providerIds = null on insert was never reached for existing rows.
Fix: Incremented the Room @Database(version = 2) and enabled .fallbackToDestructiveMigration(). This instructs Room to drop and recreate all tables when the schema version changes, wiping the cached fake data.

(This session)   Fix: onDestructiveMigration Override — Watchlist Disappeared After Schema Wipe

Problem: After bumping the database to v2, the app's watchlist was completely empty. The Room database wipe (destructive migration) cleared all rows, but the seed data was never re-inserted. This happened because the DatabaseCallback in AppDatabase.kt only overrode onCreate, which Room only calls on a true fresh install — not on schema upgrades, even destructive ones.
Fix: Added an onDestructiveMigration override to the nested DatabaseCallback class that calls the same populateInitialProvidersAndLetterboxdData coroutine as onCreate. Now when Room drops and recreates tables, it immediately re-seeds 33 watchlist items and 285 historical watch sessions from the bundled CSV assets.
Verified: Cleared app data via adb shell pm clear and confirmed in live logcat:

(This session)   Feat: Advanced Filtering & Personal Context Vault

Problem: The app was missing granular discovery tools like genre filtering and rating-based sorting. Additionally, there was no way to track personal notes or the original recommendation source (e.g., specific podcast episodes) for imported titles.
Fix:

  • Personal Context: Migrated database to v4, adding userNotes, importSource, and genres fields. The CSV parser now supports 5th and 6th columns for these values.
  • Discovery Engine: Added a dynamic Genre Filter Ribbon and a dedicated "Free w/ Ads" filter chip (targeting Tubi, Freevee, etc.).
  • Sorting: Implemented "Highest Rated" sorting based on real TMDB vote averages.
  • UI Enrichment: The Movie Details sheet now features a "Personal Context & Origins" section alongside the Monospace Agent Research vault.
Verified: Successfully imported a test CSV with custom notes and verified the "Agentic Research" section now triggers for existing items upon sync.

(This session)   Feat: Watchlist Pre-Watch Synthesis Agent

Problem: The app lacked deep contextual insights for movies added to the watchlist, requiring manual research to understand "why" a title was recommended or what its cultural significance was.
Fix: Expanded the AvailabilitySyncWorker into a full-scale research agent. In addition to availability, it now pulls movie keywords and cast details via new TMDB endpoints. This data is synthesized into a structured "Agentic Research Strategy" card (complete with YAML frontmatter) and persisted in a new trivia field in the Room database. The Movie Details sheet was updated with a monospaced "Research Vault" section to display these insights, helping users decide what to watch with professional-grade context.

(This session)   Feat: Room CSV Pre-Parser Refactor

Problem: The app's database initialization logic relied on a fragile string-splitting approach (splitCsvLine) for parsing the bundled Letterboxd CSV files. This method failed to properly handle escaped quotes (e.g., "") and commas nested deeply within multi-line fields, risking corrupted movie titles during the seed process.
Fix: Replaced the brittle splitCsvLine with a robust character-by-character RFC 4180 compliant parser. The new logic uses reader.mark() and reader.reset() to safely parse nested quotes, handles embedded commas flawlessly, and seamlessly processes fields containing newlines. The database version was intentionally not bumped to preserve any existing user watch history/intents — the new parser will cleanly apply on fresh installs or future database wipes.

Local Development — Quick Start

Prerequisites

  • JDK 17+
  • Android SDK with platform-tools (ADB) on your PATH or at C:\Users\<you>\AppData\Local\Android\Sdk\platform-tools\
  • Wireless debugging enabled on your Android phone (Developer Options → Wireless Debugging)
  • A free TMDB API key (v3 auth, read-only access)

Build & Deploy

# 1. Build the debug APK
.\gradlew.bat assembleDebug

# 2. Push to your wireless-connected phone and launch
.\deploy.ps1

Configure TMDB Key at Runtime

Open the app → Settings tab → paste your TMDB v3 API key → tap Save. Then tap the ↺ button on the Watchlist tab to immediately fetch real provider data.

Note: The TMDB key is stored in SharedPreferences on device and is never committed to source control. You do not need to set it at build time.

Database Reset (if needed)

If you need to force a full database re-seed (e.g., after adding new CSV entries), either increment @Database(version = N) in AppDatabase.kt and rebuild, or clear app data manually:

$adb = "C:\Users\<you>\AppData\Local\Android\Sdk\platform-tools\adb.exe"
& $adb shell pm clear com.aistudio.streammanager.qpwoei
